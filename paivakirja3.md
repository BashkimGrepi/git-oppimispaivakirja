# Oppimispäiväkirja: Git projektissa

__Mitä hyötyä voisi olla versionhallinnasta, jos kehität projektia yksin?__

Versiohallinnan avulla pystyn seuraamaan projektissa tekemiäni muutoksia ja palaamaan tarvittaessa aikaisempaan toimivaan versioon, jos välillä tapahtuu virheitä tai pitää tehdä muutoksia. Voin myös kokeilla uusia ominaisuuksia omissa haaroissa ilman, että toimiva versio menee sekaisin.

__Mitä hyötyä voisi olla versionhallinnasta, jos projektissa on useita kehittäjiä?__

Usean kehittäjän projektissa versionhallinta mahdollistaa sen, että kaikki voivat kehittää samaa projektia samanaikaisesti. Jokainen voi tehdä oman osuudensa omassa haarassa ja muutokset voidaan myöhemmin yhdistää yhteiseen versioon. pull requestien avulla muutoksia voidaan myös tarkistaa ja kommendtoida jos jotkin muutokset ovat kyseenalaisia ja tarvitsevat lisää muutoksia. 

__Miten järjestäisit projektitiimin versionhallinnan 3-4 hengen ohjelmistoprojektikurssilla? Laadi tiimiläisille lyhyt ohje, miten projektissa toimitaan.__

Projektissa käyttäisin yhteistä github repostitoria. main haara pidettäisiin aina toimivana versiona eikä siihen ikinä tehdä. Kaikki kehitys tehtäisiin erillisissä ominaisuushaaroissa. Ennen uuden tehtävän aloittamista haettaisiin aina uusimmat muutokset. Jokainen tekisi omat muutoksensa omaan haaraan ja tekisi ja tekisi pieniä, selkeästi nimettyjä committeja. Valmis ominaisuus puskettaisiin githubiin ja siitä tehtäisiin pull request. Joku muu kuin itse koodin tekijä tarkastaa muutoksen ennen yhdistämistä main haaraan.
